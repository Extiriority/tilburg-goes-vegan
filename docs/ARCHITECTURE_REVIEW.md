# Architecture review — 14 October 2026

The agreed stack is suitable for a small server-rendered bilingual site. SvelteKit form actions own business rules; D1 owns integrity; R2 stores public optimized photos separately from private backups. No participant accounts, payments, exports or public coordination links.

## Risks and implementation decisions

- D1: do not use application-side count then insert or interactive ORM transactions. D1 `batch()` rolls back on statement failure. Use database capacity triggers plus batched registration/outbox writes, optimistic versions for stale requests, and test on local D1. A real bound D1 validation remains a prelaunch gate, without deploying in this increment. See https://developers.cloudflare.com/d1/worker-api/d1-database/.
- SMTP: Workers TCP sockets support TLS, but port 25 is blocked. Existing provider authentication, ports 465/587 and library compatibility require a credentialed spike. No alternate provider selected. See https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/.
- Backups: binding `dump()` is legacy alpha-only. Scheduled private R2 backups require an authenticated export API workflow, bounded polling, least-privilege credentials, retention and restore drill. Time Travel alone does not establish the specified 30-day R2 retention. See https://developers.cloudflare.com/d1/worker-api/d1-database/ and https://developers.cloudflare.com/d1/best-practices/import-export-data/.
- Scheduler: the SvelteKit HTTP entry point does not itself implement a scheduled handler. Add a tested Worker wrapper or separate scheduler entry point later. Hourly due-job scans use persisted UTC instants calculated from Amsterdam wall time; public deadlines must be checked synchronously.
- Email: an outbox provides durable intent, not exactly-once SMTP delivery. A crash after provider acceptance can cause a duplicate. Decide retry handling for ambiguous acceptance; do not claim exactly-once delivery. Do not persist rendered bodies or management tokens in logs.
- Privacy: identity fields are nullable only on anonymized records. Purge recipient addresses and token rows as well as registration fields; operational logs contain codes, never transport response text. Identity deletion must not trigger capacity/state changes. Provider mailboxes, organizer Excel and backup restore cleanup need operational procedures.
- Event venue references can leak default edits into existing gatherings if venue rows are mutated. Treat referenced venue records as immutable snapshots; create a new venue row for address changes.
- UTC epoch milliseconds are the storage convention; UUIDs are generated by the application. No fabricated venue, capacity or organizer seeds. Migration does not configure production resources.
- Initial SvelteKit 2 / Svelte 5 scaffold uses the compatible Cloudflare adapter 7 and Vite 6 family; lockfile establishes exact installed versions. Framework-major upgrades are separate work.
